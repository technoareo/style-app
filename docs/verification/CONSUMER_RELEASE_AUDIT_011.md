# Consumer goal and launch evidence audit

This audit preserves the requested product: upload a single item **or a whole wardrobe photo**, extract useful visible details with minimal typing, save a private wardrobe, and suggest daily/event looks using owned items. Multiple people must be able to create and use their own accounts without an administrator creating them. Operational server access is separate from ordinary account use.

Status on 2026-10-12: working local application, not proven ready for launch. Build 011 corrected has type/diagnostic checks and one full default run passed; the 19-run matrix is incomplete. Its production compilation and fresh independent review remain pending. Previous build 010 browser evidence cannot alone prove the latest candidate.

| Requirement | Current evidence and its limit | Required before claiming completion |
|---|---|---|
| Self-service private multi-user accounts | Auth/account/backend and browser coverage exists. Email verification and recovery use captured/simulated mail in local checks. | Latest candidate regression checks, real provider delivery, HTTPS/proxy verification, capacity run and independent approval. |
| Upload one item with little typing | Browser upload/review/crop/persistence flow is tested with a **controlled analysis response**. Public single-shirt detector control works in an isolated research runtime, not the app's deployed service. | Actual app engine recognizes representative real item photos with measured correctness, latency and failure handling. |
| Upload a whole wardrobe photo | UI supports multiple review items; controlled shoe-pair/multiple-item browser fixtures test the interaction. Real dense public closet attempts fail or time out. | Actual engine on independently annotated licensed/consented held-out wardrobe images; valid boundaries, useful recall/precision, duplicate handling and acceptable end-to-end latency. No silent truncation. |
| Useful item attributes without invented hidden facts | Schema rejects malformed bounds/confidence. Review requires checking details; AI formal guesses remain suggestions. Hidden brand/size/fabric/fit must remain unknown unless visible or supplied. | Real-image attribute evaluation and review workload measurements; no confident claims about hidden details. |
| Looks made from owned items | `tests/domain.test.ts` checks completeness, dress substitution, laundry/unreviewed/hot-item exclusion, cold layering, occasion restrictions, owned-item membership and variation. | Latest regression run plus consumer assessment on real wardrobes. Algorithmic eligibility tests do not prove aesthetic quality or personalization. |
| Save, edit, reload and recover | `tests/e2e/consumer.spec.ts` covers sample wardrobe editing, saved looks, reload, backup import, invalid backup preservation and failed-save handling. | Latest compiled browser run and actual upload-to-save-to-look flow. A sample wardrobe is not proof that real clothing recognition works. |
| Safe review of multiple detections | `tests/e2e/review007.spec.ts` uses controlled service results for crop, pair confirmation, unknown formality and queued/reloaded reviews. | Real engine outputs through the same workflow on desktop and actual phones; incomplete detection must be visible to users. |
| Concurrent users and reliable jobs | Corrected default run: 136 passed, four skipped; ten isolated repeated stress runs pass. Prior default contention failure stays open. Matrix and target host/inference contention remain incomplete. | Complete matrix, measured mitigation if needed, target-host load with AI/mail/backup and state-integrity checks. No weakened stress counts or widened timeouts as a substitute. |
| Disaster recovery respects deletions | Local Windows backup/restore/ledger/presence tests provide strong logical evidence. Docker export-script omission, status/alerts and external encrypted copy remain open findings. | Correct packaged runbook, Linux/container checks and offsite recovery drill including post-backup deletions. |
| Privacy and operational safety | Ownership, input limits, private files, cancellation and session controls are covered. Physical SQLite erasure, SMTP secret scope and unhealthy-worker reporting remain open. | Resolve carried review findings and verify intended production environment. |
| Public launch | No hosting account, domain, real mail provider or deployed target exists. Docker/Linux execution and actual device testing are unproven. | Select and configure concrete services, verify TLS/proxy/email/storage/backup/health, run consumer acceptance, then joint release review. |

Inspection findings: the browser upload case intercepts `/api/analyze` and supplies fixed detections. Several consumer tests begin with the explicitly labelled sample wardrobe. These checks prove interactions and persistence, **not AI recognition accuracy**. Outfit tests prove rules and owned-item membership, **not that consumers like the looks**. This distinction must remain in every launch report.

No new shopping, social or competitor-driven feature is required to close these gaps. Work should prioritize the original photo-to-owned-outfit experience alongside the security and deployment gates. Claude implementation through VS Code and independent root verification remain the agreed workflow; a fresh Claude review must follow each candidate build.
