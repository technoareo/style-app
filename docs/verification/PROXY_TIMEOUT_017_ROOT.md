# Build 017 shared upload timeout check (2026-10-22)

Claude moved the Compose upload deadline to one non-secret project variable, `STYLE_BODY_READ_TIMEOUT_MS`. The app and proxy receive the same Compose expression; their startup shell scripts reject malformed or out-of-range values, and the proxy derives `ceil(ms / 1000) + 2` seconds for Caddy. The app refuses a legacy setting still in `.env.production` before it starts. This has **not** been run inside Docker or on Linux; only the exact shell validation text was exercised through Git for Windows `sh`.

Root checks on the final source: TypeScript typecheck exit 0; focused proxy config and shell-behavior tests **18 pass, 0 fail, 0 skip** with Git `sh` on PATH under approved local execution. Official Caddy 2.11.7 validated the config. Adapted JSON showed both `read_timeout` and `read_idle_timeout` at 22, 62 and 122 seconds for the respective proxy caps, with `protocols: ["h1"]`. These are configuration checks, not container proof.

The first live local-TLS 60/62 run found a real defect: a trickling incomplete auth body returned JSON 408 at 60.069 s and closed, but a fully stalled body received no answer or close by a 70 s watchdog. A direct compiled-app probe with `STYLE_BODY_READ_TIMEOUT_MS=60000` returned the original JSON 408 at 60.327 s; the fault was in the proxy path. Claude added `read_body_idle` at the derived proxy cap, since Caddy's one-minute default idle-body timer could otherwise fire before a longer app deadline.

Root regenerated the loopback Caddyfile from that corrected source, changing only domain/listener/upstream and adding local-only internal TLS and local test storage controls. The **corrected 60/62 TLS probe exited 0**: stalled and trickling bodies returned original JSON 408 at 60.326/60.327 s; sockets closed at 60.330/60.328 s before client cleanup. The **default 20/22 TLS regression probe exited 0**: stalled and trickling bodies returned JSON 408 at 20.320/20.321 s and sockets closed immediately. Both runs kept health 200, ALPN `http/1.1`, a reused successful health socket, `/api/health/uploads` 404, and a directly comparable private 401 status/body/Content-Type/single `Cache-Control` header (the proxy added `Connection: close`).
