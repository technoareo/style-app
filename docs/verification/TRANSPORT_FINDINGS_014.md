The client declares an incomplete body, requests keep-alive and does not end/destroy it before response; socket closure is distinguished from client cleanup.

1. **Shipped routing rules:** direct stalled/trickling auth requests return 408 around 20.3/20.2 s but sockets remain open five seconds afterward. Caddy stalled/trickling requests receive no reply before the 35 s watchdog. Both health endpoints remain 200. Slot release is not connection cleanup; a backend deadline alone does not prove bounded public-proxy response.
2. **Unshipped full-duplex/read-timeout diagnostic configuration:** `enable_full_duplex`, `read_body 22s`, `read_header 10s`. It validates and returns 408 around 20.3 s, but the stalled socket remains open even 15 s after response; trickling socket closes around 34.2 s. Both first five-second and extended runs remain failed evidence. Caddy documents full duplex as experimental; it is not proposed as an accepted fix. Evidence: `caddy-transport-candidate-014.json` and `-longer.json`.
3. **Unshipped response-close diagnostic configuration:** no full-duplex option; same separate transport caps, response matcher for upstream status 408 sets `Connection: close` before `copy_response`. Both stalled/trickling requests return the original private JSON 408 around 20.317/20.222 s. Sockets close around 20.317/20.223 s **before client cleanup**, health remains 200; no probe problems. Evidence: `caddy-close-response-014.json` (passed). This is a concrete review candidate, not a shipped source change.
4. **Broader unshipped upstream-error matcher:** status `4xx 5xx`, retaining ordinary successful-response behavior. Received auth body 32769 bytes exceeds the actual 32768-byte cap while declared length is 100000: 413 around 59 ms, socket closes around 60 ms. Unauthenticated photo with one-byte incomplete body: 401 around 58 ms, socket closes before cleanup; health 200. Evidence: `early-refusal-transport-014-corrected.json` (passed). A first root probe incorrectly expected a large declared length alone to trigger 413, and reused a timer variable so a stale watchdog marked the already-finished 401 case. That flawed source/result remains preserved; it establishes no app defect. Separate watchdog/observation timers and genuinely over-limit received bytes corrected the experiment.
