# Free local vision experiments: evidence and next decision

No app-model integration or recognition acceptance is claimed. Development probes use a public Wikimedia closet fixture, not private user photos. This fixture is not a held-out accuracy set and has no exact human garment gold labels.

Florence-2-base-ft converted ONNX model, MIT, pinned revision `e88a44eaf3791a35eae0c5a47b3dbcd36e67eb6f`: 14 allowlisted local model/config/tokenizer files. All four quantized ONNX weights were checked against upstream LFS hashes. Local-only Transformers.js 4.3.1 with ONNX WASM single-thread runtime works through the SDK's custom-runtime hook, without modifying packages or application dependencies.

- `florence-wasm-012.json`: about 40 seconds including load and two images. Single shirt produces one plausible shirt box; crowded closet produces one almost full-frame hanger box, not isolated clothing.
- `florence-regions-013.json`: dense region caption and region proposals produce the same broad hanger/full-frame region; total about 31 seconds.
- `florence-grounding-013.json`: generic clothing-category grounding completes in about 18 seconds including load. Nine returned proposals are not nine garments: several span most of the closet, one has zero width and others point to implausible regions. Do not count them as successful extraction.
- Open-vocabulary task post-processing is unsupported by this SDK path; it was not tested. No assertion that every Florence configuration fails follows from these probes.

The task-owned Ollama research process on loopback 11435 was started with cloud disabled and process-only Vulkan settings, reusing cached models. Its startup log records native CUDA and Vulkan device-discovery crashes (0xc0000005) and CPU fallback with zero discovered VRAM. Successful startup is not evidence of GPU acceleration. No driver, Windows security or global configuration was changed. The application's previous CPU endpoint remains separate.

Primary model references: https://huggingface.co/microsoft/Florence-2-base and https://huggingface.co/onnx-community/Florence-2-base-ft. GPU support reference: https://docs.ollama.com/gpu.

Next useful recognition evidence is a quiescent CPU Qwen probe using its documented native corner-coordinate format and compact structured output, followed by independently labelled, held-out single-item and crowded-wardrobe cases. Neither a single-item control nor a parser-valid result closes the original whole-wardrobe requirement. Preserve negative results and compare item coverage, crop usefulness, attribute correctness and latency before selecting a production path.

That compact native-corners CPU experiment has now completed: `qwen-compact-corners-013.mjs/.json`, cached Qwen3-VL 2B, public closet fixture, maximum 20 outputs, category and corners only, no app/model integration. It stopped normally in **87.248 seconds**, first content at 38.749 seconds, 709 generated tokens. It returned 20 repetitive category `top` strips at identical vertical coordinates; one box is reversed (`[970,435,104,999]`) and later boxes repeat the earlier horizontal range. Geometry validation failed. This is another negative development result, not 20 detected garments or a held-out accuracy score. Removing color/pattern/name fields reduced output but did not produce useful isolated items. The owned service log reports all inference slots idle afterward; no GPU acceleration was discovered.

13 October follow-up: same compact schema/image/768px/CPU baseline with the cached larger **Qwen3-VL 4B**. `qwen-compact-corners-4b-014.json`: normal completion in **60.055 seconds**, first content 53.976 s, 44 generated tokens. It returned one `top` box `[0,368,1000,999]`, spanning the full image width and most of the clothing region. Geometry is valid; it does not separate the many visible garments. Do not turn parser success into extraction success or count this as one correctly isolated item. This is a development-only negative/inconclusive result with no independent human gold accuracy score. No application integration occurred. The task-owned cloud-disabled CPU research service was identity-checked, confirmed to have no loaded model, and stopped after the probe; existing application/Ollama services were not stopped by that cleanup.
